## 0. Loyiha haqida umumiy ma'lumot

**Maqsad:** Foydalanuvchi Telegram'ga kirmasdan, faqat o'zi belgilagan odam/guruh/kanallardan
kelgan xabarlarni ko'ra oladigan tizim yaratish. Bu Telegram'ga bo'lgan chalg'ituvchi
qaramlikni kamaytirib, faqat muhim (masalan, kurs o'qituvchisi, muhim guruh) xabarlarni
alohida, minimalistik interfeysda ko'rsatadi.

**Foydalanuvchi muhiti:**
- Backend: AWS server (Ubuntu, SSH orqali key-fayl bilan ulaniladi), doim ishlab turadi (24/7)
- Frontend: Mac kompyuter, brauzerda ochiladigan, lekin "kichik desktop oyna" ko'rinishida
  (masalan Chrome "Create Shortcut... > Open as window" yoki shunga o'xshash usul bilan)
- Konfiguratsiya (kuzatiladigan odam/guruh/kanal ro'yxati): veb-sahifadagi forma orqali
  qo'shiladi (@username YOKI raqamli Telegram ID — ikkisi ham qo'llab-quvvatlanishi kerak)

**Texnologik stack (o'zgarmas, har bir bosqich shunga rioya qiladi):**
- Backend tili: Python 3.11+
- Telegram bilan ishlash: Telethon kutubxonasi (MTProto, userbot rejimida — foydalanuvchi
  o'z shaxsiy akkaunti bilan bir marta login qiladi, keyin session fayli saqlanadi)
- Backend server: FastAPI + Uvicorn
- Baza: SQLite (fayl: `data/focus.db`), SQLAlchemy (async, `aiosqlite`) orqali
- Real-vaqt yangilanish: WebSocket (FastAPI ichida, qo'shimcha servis shart emas)
- Frontend: oddiy HTML + CSS + vanilla JavaScript (hech qanday build-tool, npm, webpack
  ISHLATILMAYDI — bitta yoki bir nechta oddiy static fayl, chunki Mac'da "oyna" sifatida
  ochish uchun eng barqaror va murakkabликsiz yo'l shu)
- Muhit o'zgaruvchilari: `.env` fayl orqali (`python-dotenv`)

**Umumiy papka strukturasi (barcha bosqichlar shunga rioya qiladi, o'zidan struktura
o'ylab topmaydi):**

### BOSQICH 2 — Ma'lumotlar bazasi va Telethon (Telegram) mijozi
**Kim bajaradi:** Bosqich 1 tugagach.
**Bog'liqlik:** `backend/requirements.txt` va `.env.example` mavjud bo'lishi kerak
(`STATUS.md`dan tekshiring).
**Vazifa:**
1. `backend/app/database.py` — SQLAlchemy async engine, session yaratish, `Base` klassi.
2. `backend/app/models.py` — ikkita model:
   - `Source` (kuzatiladigan manba): `id`, `identifier` (username YOKI raqamli ID, matn
     sifatida saqlanadi), `display_name`, `type` (enum: `user`/`group`/`channel`),
     `is_active` (bool), `created_at`.
   - `Message`: `id`, `source_id` (Foreign Key), `sender_name`, `text`, `media_type`
     (nullable — matn, rasm, video va h.k.), `media_path` (nullable, agar media saqlansa),
     `telegram_message_id`, `received_at`, `is_read` (bool, default False).
3. `backend/app/telethon_client.py`:
   - Telethon `TelegramClient` ni `.env`dagi `TELEGRAM_API_ID`/`API_HASH`/`PHONE` bilan
     ishga tushirish funksiyasi.
   - **Birinchi marta login** qilish oqimi alohida, aniq kommentariyalar bilan yozilsin
     (Telegram SMS/kod so'raydi — bu **interaktiv** jarayon, avtomatlashtirilmaydi,
     foydalanuvchi buni terminalda qo'lda bir marta bajaradi; keyin session fayl
     saqlanadi va qayta so'ralmaydi).
   - `client.on(events.NewMessage)` handler — har bir kelgan xabar uchun:
     a) Xabar kimdan/qaysi chatdan kelganini aniqlash (username va raqamli ID, ikkisini
        ham oling — chunki foydalanuvchi ikkisi bilan ham qidirishi mumkin).
     b) Bazadagi faol (`is_active=True`) `Source` ro'yxati bilan solishtirish
        (username case-insensitive solishtirilsin, `@` belgisiz va bilan ham ishlasin).
     c) Agar mos kelsa — `Message` jadvaliga yozish.
     d) Keyingi bosqich (3) uchun: yozilgandan keyin WebSocket orqali xabar
        yuborilishi kerak bo'ladi — buning uchun oddiy Python `asyncio.Queue` yoki
        callback funksiya orqali "hook" qoldiring (masalan
        `on_new_filtered_message: Callable` parametri), to'liq WebSocket integratsiyasini
        Bosqich 3ga qoldiring.
   - Xatolarni ushlash: flood-wait, ulanish uzilishi holatlarida log yozib, qayta
     urinish (retry) logikasi.
4. Buni alohida ishga tushiriladigan skript qilib yozing: `backend/app/telethon_client.py`
   to'g'ridan-to'g'ri `python -m app.telethon_client` bilan ishga tushsa ham, FastAPI
   ichidan `import` qilib background task sifatida ham ishlatilsin (ikkala holat uchun
   ham mos struktura).
5. Web qidiruv orqali Telethon'ning eng so'nggi versiyasidagi `events.NewMessage`,
   session fayl formati va login oqimi o'zgarmaganini tasdiqlang.
6. `STATUS.md`ga yozuv qo'shing — MUHIM: bu bosqich odatda **real Telegram akkaunti
   bilan sinalmaydi** (chunki API kalitlari yo'q), buni ochiq yozing va qo'lda qanday
   sinash kerakligini tushuntiring.

**Chiqish:** `backend/app/database.py`, `backend/app/models.py`,
`backend/app/telethon_client.py`, `STATUS.md`ga yangi yozuv.

### BOSQICH 3 — FastAPI backend (REST API + WebSocket)
**Kim bajaradi:** Bosqich 2 tugagach.
**Bog'liqlik:** `models.py`, `database.py`, `telethon_client.py` mavjud bo'lishi kerak.
**Vazifa:**
1. `backend/app/schemas.py` — Pydantic modellari: `SourceCreate`, `SourceOut`,
   `MessageOut` va h.k.
2. `backend/app/routers/sources.py`:
   - `POST /api/sources` — yangi manba qo'shish (`identifier`, `display_name`, `type`)
   - `GET /api/sources` — ro'yxatni olish
   - `PATCH /api/sources/{id}` — faollashtirish/o'chirish (`is_active`)
   - `DELETE /api/sources/{id}`
3. `backend/app/routers/messages.py`:
   - `GET /api/messages?source_id=&limit=&offset=` — tarixni olish, eng yangisi birinchi
   - `PATCH /api/messages/{id}/read` — o'qilgan deb belgilash
   - `WebSocket /ws/messages` — yangi xabar kelganda real vaqtda frontend'ga jo'natish
4. `backend/app/main.py`:
   - FastAPI ilova, routerlarni ulash
   - CORS middleware (`.env`dagi `ALLOWED_ORIGINS`)
   - Ilova ishga tushganda (`startup` event) Telethon clientni background task
     sifatida ishga tushirish, `on_new_filtered_message` callback orqali WebSocket'ga
     ulash (Bosqich 2dagi hook shu yerda ishlatiladi)
   - Statik fayllarni (frontend) xizmat qilish IXTIYORIY — agar oddiy bo'lsa, xohlasa
     shu yerda `StaticFiles` bilan ulasin, bo'lmasa frontendni alohida ochish
     yo'riqnomasini Bosqich 5ga qoldirsin.
5. Har bir endpoint uchun asosiy xatoliklarni boshqarish (404, validatsiya xatolari).
6. Mumkin bo'lsa, `uvicorn` bilan lokal ishga tushirib, kamida `GET /api/sources`
   endpointini sinab ko'ring (real Telegram ulanishisiz ham bu ishlashi kerak — agar
   Telethon client login qilinmagani sababli xato bersa, buni try/except bilan
   yumshatib, FastAPI umuman ishga tushmay qolmasligini ta'minlang).
7. `STATUS.md`ga yozuv qo'shing.

**Chiqish:** `backend/app/schemas.py`, `backend/app/routers/sources.py`,
`backend/app/routers/messages.py`, `backend/app/main.py`, `STATUS.md`ga yangi yozuv.

### QO'SHIMCHA TALAB: Avtomatlashtirilgan Robust O'rnatish va Deploy Tizimi (`setup.sh`)

Loyihada foydalanuvchi serverga kirganda bitta buyruq (`bash scripts/setup.sh`) bilan butun tizimni sozlay oladigan avtonom, mustahkam (robust) skript yaratilishi SHART.

Skript quyidagi algoritmni to'liq o'z ichiga olishi va xatolarni oldini olishi (fault-tolerant) kerak:

1. **Pre-flight Checks (Avtomatik tekshiruvlar):**
   - OS tekshiruvi: Ubuntu/Debian ekanligini aniqlash.
   - Python 3.11+ mavjudligini tekshirish; agar yo'q bo'lsa, foydalanuvchiga xabar berib, `software-properties-common` va `python3.11-venv` paketlarini avtomatik o'rnatish.
   - Port tekshiruvi: 8000-port boshqa dastur tomonidan band qilinmaganini tekshirish (`lsof` yoki `netstat`). Agar band bo'lsa, ogohlantirish berish va boshqa port tanlashni taklif qilish.

2. **Interaktiv Konfiguratsiya (Wizard):**
   - Agar `.env` mavjud bo'lmasa, terminalda chiroyli ko'rinishda foydalanuvchidan quyidagilarni birma-bir so'rash:
     * Telegram API ID (faqat raqam kiritilishi tekshiriladi)
     * Telegram API Hash (bo'sh emasligi tekshiriladi)
     * Telefon raqami (+998... formatda)
     * Backend porti (default: 8000)
   - Kiritilgan qiymatlarni tasdiqlatish va xavfsiz holda `backend/.env` fayliga yozish (fayl huquqlarini `chmod 600` qilib belgilash).

3. **Muhitni avtomatik tayyorlash:**
   - `python3 -m venv venv` orqali virtual muhit yaratish.
   - `pip install --upgrade pip` va `pip install -r requirements.txt`ni xatolarsiz o'rnatish. Har qanday xato yuz bersa, to'liq logni chiqarib, to'xtash (`set -e`).
   - SQLite uchun `backend/data/` papkasini yaratish va unga to'liq yozish (`r/w`) huquqini berish.

4. **Interaktiv Telethon Autentifikatsiyasi (Bir martalik kirish):**
   - Skript orqali vaqtinchalik `python -m app.telethon_client`ni ishga tushirib, foydalanuvchiga terminalda Telegram tasdiqlash kodini va (agar bor bo'lsa) 2FA parolini kiritishiga imkon berish.
   - Sessiya fayli (`.session`) muvaffaqiyatli yaratilganini tekshirish. Agar xatolik bo'lsa, sababini aniq ko'rsatish (masalan, "Kod noto'g'ri kiritildi").

5. **Systemd Servisini Avtomatik Yaratish va Ishga Tushirish:**
   - Loyiha joylashgan aniq yo'lni (`pwd`) va serverdagi foydalanuvchi nomini (`$USER`) avtomatik aniqlab, `/etc/systemd/system/telegram-focus.service` faylini generatsiya qilish.
   - `systemctl daemon-reload`, `systemctl enable telegram-focus` va `systemctl start telegram-focus` buyruqlarini bajarish.

6. **Post-Deployment Healthcheck va Rollback:**
   - Servis ishga tushgach, skript 5 soniya kutib, `curl -s http://localhost:8000/docs` orqali backend ishlab turganini tekshiradi.
   - Agar servis ishga tushmasa (`systemctl is-active --quiet telegram-focus` false bo'lsa), skript darhol `journalctl -u telegram-focus -n 30 --no-pager` xatolik loglarini ekranga chiqaradi va muammoni bartaraf etish yo'lini ko'rsatadi.
